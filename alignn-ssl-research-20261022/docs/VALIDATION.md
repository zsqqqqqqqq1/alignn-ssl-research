## 自监督开关补充验证

- WSL my_alignn 环境完整 CPU 测试：22 项通过。包括配置内开关分发、同一配置参数复用、混合开关拒绝、旧协议配置兼容、原版模型数值一致性和纯监督中断恢复测试。
- 纯监督两轮小测试：连续训练与中途保存后恢复的权重、历史和最终预测一致；配置变化会拒绝恢复。
- 4 个真实训练材料，hidden256、4+4 层：相同权重下，当前无掩码主干封装与原版 ALIGNN 的 train/eval 输出、梯度和一次 AdamW 更新均相同（最大绝对差为 0）。未连接参数集合也一致。结果见 `provenance/alignn_call_audit.json`。
- 直接核对本机已有正式实验protocol：有效配置、核心源码和原调度入口哈希完全一致。统一入口开关 true/false 的 `--check` 均通过，没有启动正式训练或创建数据副本。
- 新 ZIP 的 CRC、解压字节一致性及文件 SHA-256 清单校验。

上述检查支持已覆盖范围内的模型调用一致性，不能证明完整 300 轮结果相同，也不能据此断定自监督效果差的原因。监督分支直接调用原版模型 forward，但保留本项目的数据迭代、优化和断点框架，不等于逐行调用历史基线的整套训练脚本。

## 接收方复核命令

完成环境安装后，在仓库根目录运行：

```bash
python tools/verify_package.py
python tools/check_environment.py --require-cuda
CUDA_VISIBLE_DEVICES='' MPLBACKEND=Agg python -m unittest discover -s tests -v
python tools/verify_dataset.py --data /path/to/data10000
bash run_formal_wsl.sh --check
```

完整测试包含合成晶体的构图、掩码、投影梯度、冻结权重、断点恢复、三组调度和终端显示等检查。它们不会自行启动 300 轮正式训练，也不应指向现有正式实验目录。

修改 所选 `configs/formal_*.json` 后，文件校验工具会正常提示它与发布版不同；这是预期的用户配置修改。
